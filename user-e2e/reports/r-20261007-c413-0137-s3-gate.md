## 探针机制发现（e2e 侧，非 ③ 产品缺陷）

- **compact 调用识别面**：proactive 富体 / reactive 富体 / headless 窄体三支 compact 摘要调用**都用 `mainLoopModel`（model/role 不可判别）**，但请求体都含 `getCompactPrompt` marker → `detectCompact(body)` 匹配 `CRITICAL: Respond with TEXT ONLY` / `Your task is to create a detailed summary`（主循环自然对话不含此串）→ 三支通用识别稳。实证：proxy `compact=SUCCESS/FAIL` 精确命中 compact 调用。
- **D2 跳闸态触发口径订正**：设计初稿假设「3 次 proactive 失败各 1 compact 调用」；实证 rich `compactConversation` 内部有重试（`MAX_PTL_RETRIES`），单次 auto-compact 尝试可发多个 compact LLM 调用。`consecutiveFailures` 按 **autoCompactIfNeeded 失败次数**（非 compact LLM 调用数）累加（`autoCompact.ts:558`）→ 探针用 `compactFailN=999`（全 compact 恒败）+ context 恒高 → 3 次 auto-compact 失败 → store=3 跳闸 → ① 渲染。**关键：跳闸态只在「context 仍 > 阈值 且 store≥3」时渲染；若 compact 曾成功（context 降）则 warning 消失 → ① 需 context 恒高场景（无 413/无成功压缩）才可捕获**。
