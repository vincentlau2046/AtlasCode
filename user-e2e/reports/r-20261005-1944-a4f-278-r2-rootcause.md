## R2 根因（钉死，推翻 R0「skip 早退」为不完全定位）

**setAllowVerdict 加在 useCanUseTool 的 allow 支，但 REPL 主权限门 = engine 门（buildInteractiveGate），确定性 allow 走 engine 快路径短路、永不达 useCanUseTool。**

白盒链：
1. `loopPermissionBridge.ts`（W3-3b §8.74.15，**REPL onQueryImpl checkPermission 接缝，主权限门**）L61 `engineGate = createPermissionGate(...)`；L77 `verdict = await engineGate(tool, input)`；**L78 `if (!verdict.ask) return verdict`** —— engine 门确定性 allow/deny 直接返回，**不重跑 TUI canUseTool**（L79-87 canUseTool 只在 ask 支）。
2. `engine/permissions/permissionGate.ts` L69 allow 决策返 `{ allowed: true, updatedInput }` —— **allow verdict 不携带 decisionReason**（deny/ask 才带 reason）。
3. `useCanUseTool.tsx` L42-56：`if (result.behavior === 'allow') { ... setAllowVerdict(...) }` —— 该 allow 支在 REPL 主路径**只在 ask 支经 canUseTool 重跑时可达**；auto-allow（rule-allow 2b / bypass 2a / yolo classifier-approve）被 engine 门快路径短路，**setAllowVerdict 永不触发**。
4. ⇒ `allowVerdicts` Map 恒空 → `allowVerdictLine` 恒 null → 即使 R1 `hasSuccessCardMarker` 早退门正确，也无 marker 可放行 → allow 面三句（rule-allow/bypass/classifier-approved）永不渲染。

**R1 定位（successCardRenderMode 'skip'）非真因**：skip 早退只在 allowVerdictLine 非 null 时才 `!hasMarkerLine` 放行；但 allowVerdictLine 恒 null（数据层 setAllowVerdict 未触发），故 R1 修对 a4rallow/a4bypass 是 no-op。R1 只修了「万一有 marker 时别挤掉」的次级面。

**同类靶**：`setYoloClassifierApproval`（yoloReason，classifier-approved 句数据源）在同一 useCanUseTool allow 支（L46-48），同被 engine 门快路径短路 → classifier-approved 句未来 live 模型可达时同样不渲染。

## 修法建议（R2，供 Main）

两条路择一（推荐 ①，数据源不动、只补快路径记录点）：
1. **engine 门 allow verdict 携带 decisionReason + 桥层记录**：
   - `permissionGate.ts` L69 allow 返 `{ allowed: true, updatedInput, decisionReason }`（GateVerdict 加可选 decisionReason 字段，deny/ask 已知）。
   - `loopPermissionBridge.ts` L78 前：`if (!verdict.ask) { if (verdict.allowed && verdict.decisionReason) setAllowVerdict(toolUseID, { reason: verdict.decisionReason, mode: tpc.mode }); return verdict; }`（toolUseID = callContext.toolUseId，需在 return 前落 Map，挂载读即删同现模式）。
2. 若 engine 门不便带 decisionReason：在 `buildInteractiveGate` 收到 allow verdict 时反查 allow 规则/bypass 自行合成 reason（不推荐，句式易漂移）。
- 附带：classifier-approved 的 yoloReason 记录点同样需移到 engine 门 allow 快路径（或桥层），否则 live 模型可达后仍不渲染。
