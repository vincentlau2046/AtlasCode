## §3 RED 定因——切片 3 InlineViewportCompressor 收缩环自激崩溃

**现象**：G5 场景 turn-1（1200 行流式 + 序列 Write tool_use，default 权限 + ask Write）流式中后段 TUI 崩溃，权限 dialog 从未渲染（'Do you want to' = 0），后续回合不可入（G5d RED）。

**铁证**（`pty/G5-stream-pin/pty.log`）：
- 崩溃栈直指 `src/tui/components/InlineViewportCompressor.tsx:84`（`setShrinkRows(prev => prev + overflow + 1)`）
- React `Maximum update depth exceeded`（react-reconciler dispatchSetState ← commitHookLayoutEffects 循环）
- 时点 = 流式进行中（spinner「Generate long test text」+「9/17 行已入滚动区」提示在场）

**根因判读**：实测收缩环（`useLayoutEffect` per `[scrollable, bottom, rows, plan]`）在流式每帧内容增长下，溢出收缩不可收敛（或收缩后测量值仍 > 视口，如 bottom 槽增长/帽下限抵消）→ 溢出恒 >0 → setState 无限自激。注释「溢出 >0 才 setState（无环自激）」的收敛假设在流式增长 + 压缩下限场景不成立。Main 侧 unit `p0-viewport-compressor.test.ts` 预算分配序格未覆盖「不可收敛溢出」面。

**副观察（登记债）**：切片 2-A crash 升格行 = 0——Ink 渲染环内抛出未被 uncaughtException/crashRecovery 升格捕获（错误行系 Ink 原生 fallback 上屏，进程死亡面）。2-A 升格注册面与 Ink 渲染错误边界的关系建议登记排查。
