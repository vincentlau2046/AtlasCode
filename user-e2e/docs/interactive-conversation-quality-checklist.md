# T9 交互式多轮沟通测试 · L2 质量评审 checklist（人工）

> **配套**：T9 `conv` tier 的 L1 结构断言已自动化（每轮响应/输入面活/工具轮磁盘/上下文关键词代理），
> 落 `artifacts/<runId>/transcript-conv-*.md`（已剥 ANSI 的全对话转录）。
> **本 checklist = L2 质量断言**，无法自动（响应切题/多轮连贯/纠正采纳/无 fabrication 需人判断），
> 评审人读 transcript 逐条打勾，附证据行号。

## 为什么需要 L2（L1 测不到的）

L1 结构断言能抓「首条复杂消息无响应」「多轮断」「工具轮无磁盘产物」——这些是**管道级**故障。
但 L1 测不到「响应是否切题」「上下文是否真连贯（不是嘴上提了词但答非所问）」「纠正是否真采纳（承认但没改）」「是否 fabrication（声称完成但磁盘证伪）」——这些是**语义级**质量，需人读对话判断。

## 评审方法

1. 打开 `artifacts/<runId>/transcript-conv-<script>.md`（3 个脚本各一份）
2. 对照下方 checklist 逐条评审
3. 每条：✅ 达标 / ⚠️ 部分 / ❌ 不达标，附转录里的证据片段或行号
4. 汇总：脚本级质量分（5 条全 ✅ = 合格；有 ❌ = 质量缺陷，即使 L1 PASS）

## 与 L1 verdict 的关系

- **L1 FAIL/STUCK** = 管道级故障（首条无响应/多轮断/工具无产物）→ 产品缺陷，直接修
- **L1 PASS 但 L2 有 ❌** = 语义级质量缺陷（响应了但答非所问/承认但没改/声称完成但没做）→ 更隐蔽，需产品+模型面改进
- **L1 PASS + L2 全 ✅** = 合格（该任务面）

L2 不进自动判级（不阻塞 CI/全量跑），作为**深度体检项**定期人工评审。
