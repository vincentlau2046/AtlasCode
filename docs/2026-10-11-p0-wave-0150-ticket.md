## 1. 落码规格（Main 车道）

### 1.1 AD-22 — PreCompact hook block 消费支（CC 2.1.105，TOP 压缩簇）

- **缺口定位（PAC 卡 D1/D2）**：`'PreCompact'` 已 in 事件 enum（`hookEvents.ts:21`）+ 匹配侧 `getMatchingHooks.ts:97 case 'PreCompact'`（hook 可**触发**）；**缺 = block 消费支**（compact 触发点是否 honor `exit 2` / `{decision:"block"}` 阻断压缩，现未命中 = 推断需补）。
- **改法（1 件）**：compact 触发点（`engine/context/compact*.ts` + `loopDeps.ts:245-252` compactConversation）新增 PreCompact block 消费——压缩执行前发射 PreCompact hook，返 `decision:block` / exit-2 → **跳过压缩**（不压缩 + 记 skip 原因）；不 block → 正常压缩。
- **零回归约束**：未配置 PreCompact hook → 压缩路径与现逐字恒等。
- **判别单测**：① PreCompact 返 block（exit 2 / decision:block）→ 压缩被跳过 + 记 skip 原因（**修前红**，现不 honor）② 不 block → 正常压缩 ③ 无 hook 配置 → 零回归。

### 1.2 FX-31 — transcript 写失败记日志（CC 2.1.101，纯修复）

- **缺口定位（PAC 卡 D2）**：写侧 `record.ts` recordTranscript 写失败（磁盘满 EIO/ENOSPC）**静默丢、不记日志**（读侧 `load.ts:363`「write topology already on disk」= 读侧修，非写侧）；直接命中「不静默丢」主诉。
- **改法（1 件）**：recordTranscript 写失败支加日志（error + 路径 + 原因，非静默），不改写语义（写失败仍不阻断主流程，只记日志）。
- **零回归约束**：写成功路径零变更。
- **判别单测**：mock fs 抛 EIO/ENOSPC → 断言 log 有记录（非静默）（**修前红**，现静默丢）→ 修后绿。

### 1.3 FX-35 — `--resume` 缺 file_path tool result 崩（CC 2.1.97，纯修复）

- **缺口定位（PAC 卡 D2）**：resume-load `convertToLogOption`（tool result 反序列化）对持久化 Edit/Write tool result **缺 `file_path` 无容错 → 崩**（`search.ts:177` 仅搜索展示列，resume-load 容错未命中 = 推断需补）。
- **改法（1 件）**：resume-load 对缺 `file_path` 的 tool result 加容错支（降级/跳过，不崩）。
- **零回归约束**：正常 tool result（含 file_path）零变更。
- **判别单测**：构造缺 `file_path` 的持久化 Edit/Write tool result → resume 不崩（降级/跳过）（**修前红**，现崩）→ 修后绿。

### 1.4 FX-04 + PT-04 — invoked-skill 保全 + 提示词（CC 2.1.119）

- **FX-04（verify）**：`compactPorts.ts:110 buildPostCompactAttachments`（附件重建簇 file/plan/**skill**）+ `compact.ts:556` + `processPromptSlashCommand.ts:19 ③ addInvokedSkill` + `skill/index.ts:161-163 clearSkillUsageState/recordSkillUsage` → invoked-skill 态跨压缩保全自动备；**verify = 实核压缩前调 skill → 压缩后下一条消息 skill 态只作上下文、不重执行 setup action**（判别单测；若 verify 发现真重执行 → 加 1 处加固，修前红→绿）。
- **PT-04（提示词落码，随 FX-04 同波）**：System Reminder「Previously invoked skills」= 压缩后恢复压缩前调用的 skill 作 context only + 含「勿重执行 setup」措辞；判别 = 提示词在场断言（压缩后 reminder 在场 + 「勿重执行」措辞）。

### 1.5 FX-30 / FX-34 — verify 项（未 cover / 缺 gap 则升级落码）

- **FX-30（seen 环）**：`load.ts:8` buildConversationChain **seen 环检测** + `record.ts:201-211 seenNewMessage && isChainParticipant` 锚点守卫 → 自引用环已有 seen 检测；**verify = 构造自引用 message 的 transcript → resume 不截断/不死循环**。若 verify 发现大 session 面未 cover → 升级大建（D6 中→大），**重排波 + 知会用户**（非静默吞）。
- **FX-34（dead-end 桥接）**：`load.ts:212-217`「buildConversationChain reconstructs the full unsnipped history... has parentUuid pointing INTO the gap... would hit」gap 重建已备 + seen 环；**verify = dead-end 分支大 session → resume 锚 live 会话 + 不串入无关子会话**。若 verify 发现桥接/隔离缺 gap → 升级落码。

## 2. follow-up 3 件核销规格（用户 2026-10-11 裁定合入 0.1.50）

### 2.1 C3 — timeoutlane 活面复实证（Main 车道探针健壮性工单）

- **0.1.49 gate 定因（既有行为，非 0.1.49 回归）**：settings `llmTimeoutMs=8000` + proxy delay 15000ms 下 **12 次调用 × 8s 定间隔 ≈ 90s 窗耗尽、无「Request timed out」终态行**（请求级 8s 超时活，但每次超时被 **R1 有界重试吸收** → 重试预算耗尽静默终）；0.1.47 基线（4dfc194 同 Qwen38 面）同签名 FAIL（ms=90021/proxyCalls=12/timedout=false）= 既有行为；0.1.49 八提交与 timeout/retry 路径零交集。
- **核销 = timeout × R1 重试交互活面复实证，定因「哪个签名才对」**：
  - 若 **R1 吸收 = 正确行为**（设计：有界重试吸收瞬时超时）→ 修探针期望（e2e 测试侧：timeout lane 探针断言「重试预算耗尽静默终」签名，非「Request timed out」终态行）= 探针修；
  - 若 **超时终态应现形**（10-04 PASS 签名 8159ms/1 call = 产品曾现形终态）→ 修产品（Main 落码：timeout 终态语义对齐）= 落码。
  - **判定依据 = 10-04 PASS 签名（8159ms/1 call）与现 12-call 签名的行为演化定因**（何时从 1-call 变 12-call、改了什么）。
- **零回归**：FX-36 超时面三态判据（单测 10/10）不变；本项仅对齐 C3 探针/超时终态语义，不改 resolver cap。

### 2.2 F-1 — `CMP_MODEL` 探针模型口径（**2026-10-11 用户裁定核销 = 通即行，不探不绑**）

- **用户裁定原文（2026-10-11）**：「deepseek，不需要探，本质上云上 provider 是经常换的，模型只有有通的就行。」= **探针模型口径 = 可达性（当前通的模型即用），不绑定具体云模型、不探云配额、不等待配额恢复**（云 provider/模型经常换，绑具体模型无意义）。
- **处置**：F-1 **闭环为一条固定口径（非开放决策门）**——gate 时 CMP_MODEL = **当时可达的模型**（0.1.50 现况 = deepseek 429 不可达 → 用 Qwen38-27B-TXT；日后云模型换/恢复 → 用其时可达者，**无需用户逐次裁定、无需 f4 探配额**）。
- **0.1.50 gate 默认 = Qwen38-27B-TXT**（CMP_MODEL 工作树现值，`3fd33e3` 已收编）；若 gate 时恰有云模型可达，用之（e2e 自判，非发布门禁）。
- **F-1 核销**：本波即闭环（口径确立 = 不再挂账）；`ATLAS_E2E_LB_MODEL`/`CMP_MODEL` 维持 e2e 可切机制，但**判据从「等 deepseek 恢复」改为「用可达模型」**。

### 2.3 F-2 — V3 soft×2 INCONCLUSIVE 复实证（e2e 探针健壮性）

- **背景**：0.1.37 ⑧ 封口面（pane-worker useSwarmPermissionPoller 300ms→780ms fail-closed deny）在 0.1.48 gate V3 soft×2 INCONCLUSIVE（worker 自退 t=1040ms < deadline 10s，⑧ 封口现形触发未达，既有行为非本波回归）。

- **零回归**：V3 主断言（跨进程 mailbox 信道 + 干净自退）不变。
