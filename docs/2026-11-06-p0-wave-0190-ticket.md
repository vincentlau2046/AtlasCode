留痕通道：AtlasCode 无 telemetry sink（0.1.89 已删）→ `logForDebugging`（`../shared`，modelprovider 域既有先例 index.ts:58 / modelprovider.ts:528）+ 防御函数返回值 `repaired` 留痕标志（判别单测可断言，禁静默）。修复只触 tool_calls/tool_result 形：正向补合成 error result（role:'tool' 纯文本 + tool_use_id 回指 + is_error 形），反向剥孤儿 tool_result 投影；零 attachment 语义越权（0.1.89 登记面不动）。

### 5.2 必答③（RF7）microCompact 自有 slicing 面实核 = 豁免成立

直证三支（microCompact.ts 全文实读 @ worktree）：
- 裁剪模式 `trimmedMicrocompactMessages`（:277-321）：`messages.map` 内对 clearSet 命中的 tool_result **block 内容替换**为 `TIME_BASED_MC_CLEARED_MESSAGE`——tool_use_id 与块本体保留，消息数组零切片，配对无损。
- 富模式 `maybeTimeBasedMicrocompact`（:424-484）：同形 block 内容替换（+warning 抑制/cache 态重置配对），零消息级 slicing。
- cached-MC 支（:509-517）：经 `port.cachedMicrocompactPath`（cache-edit 服务端路径；缺省 stub 恒等返回；真实现语义 = cache_edit 不删消息），非本仓 slicing 面。
- 佐证：floor-1 注释（:289/:438 `slice(-0)` 保全部）说明该文件唯一切形数的地方是 id 集合 `slice(-keepRecent)`（保留最近 N 个 **tool_use_id**），仍落在 block 替换域内。

结论：microCompact 三支均不产生孤儿 tool_use/tool_result 边，**豁免成立**；其输出仍被层 2 出口防御统一覆盖（出口终态检查与来源无关）。

### 5.3 必答②（RF3）连击注入槽位选型 = in-band user+isMeta（走 C85-B ToolResult.newMessages 既有交付链）

**裁定：in-band user+isMeta，不走 attachment 路线。** 论证：

1. **engine wire 可达性硬条款**：in-band user 消息天然进 wire。C85-B 交付链已在场且全链验真（0.1.85-B）：`ToolResult.newMessages` → `sanitizeSupplementalMessages`（toolExecution.ts:360-413，user + isMeta:true + 稳定 uuid/timestamp + sourceToolUseId 关联）→ runToolBatch 携带 → queryOneRound 追加进 roundMessages（tool_result 之后、defer 标记之前）。注入点 = 工具执行后置面，连击守在 executeToolUse 成功支产出 tool_result 后判定 count 命中阈值时产出 newMessages（text-only user+isMeta），**零新投递面**。
2. **attachment 路线排除理由**：① 0.1.89 未知族显式拒绝 marker（fail-visible）会把未登记的 reminder attachment 自己拒掉——须同波入 attachmentProjection 投影登记表，多一张登记面 + 多一层投影分叉；② reminder 是纯文本建议（无 id/无源媒体/无渲染面），套 attachment 形状是语义错配（attachment = 上下文媒体/状态面，reminder = 即时建议）；③ DSH 原型同为 UserMessage 注入（PLUGIN_SOURCE kind:'plugin' form:'notice'），非 attachment 族。
3. **C85-B 合形**：产出经 sanitizeSupplementalMessages 同一合法化面（user+isMeta+text 块），天然满足工单「无论何者须 C85-B 合形且逐族登记」——本选型下登记面 = newMessages 通道（既有），非 attachment 登记表（不动 0.1.89 面）。
4. **DSH 语义映射与 delta 登记**：计数键 = `[toolName, canonicalize(arguments)]`（deep key-sort 规范化，DSH :89-105 同语义——属性序不同视为同调用）；连续 = 无其他**tracked**工具调用插入（DSH :176-179：exclude 工具透明——不计数也不清零，include 缺省=全跟踪）；成败均计数（DSH :185-188 denied 也流经 post-execute——AtlasCode 侧执行后置判定天然覆盖 error 短路支以外的成败两态；defer 挂起支不产 tool_result 不计）；**delta**：DSH user-interjection pre-step 清零支不迁（工单 Review Focus 2 已裁定进程内生命周期计数、agent run 结束即弃、不清零特判，最小面）；per-agent 隔离 = 计数状态随执行上下文（run 生命周期 Map，同 DSH WeakMap<Agent,Chain> 形态）。
5. **阈值/配置纪律**：默认 `[3,5,8]` + `argumentsPreviewChars` 500 头截断（detailed 提醒引参上限，检测用全量 canonical 串——DSH :118-121 同语义）；配置校验 fail-loud（空表/非整数/<2/重复 → 构造时抛，DSH validateThresholds :128-141 同纪律）；首阈 = gentle 文案、后续 = detailed 文案（tool+count+preview）——两级文案照 DSH 语义自含实现（非逐字 vendor）。

### 5.4 层 1 切点形态定谳 = assistant 回合边界回退（上游 grouping 语义），非 DSH 平衡边

**裁定：取 assistant API 回合边界回退。** 理由：

1. 上游 2.1.88 grouping.ts:5-50 实读：边界 = 新 assistant message.id（流式同响应共享 id，`groupMessagesByApiRound` 唯一门 = id 变更）；「合法对话下配对有效性自然成立；追踪未决 tool_use 只在畸形输入时起作用且会 pin 死分组——让边界照常触发，ensureToolResultPairing 在 API 时修复」。AtlasCode 层 1 取同语义的选择时策略 + 层 2 兜畸形输入，两层互补对齐上游。
2. DSH 平衡边（inProgressToolCalls 归零）在 AtlasCode 消息形下需逐消息扫描 content 块数增量维护，且与审计 RF1「消息级整组、避免块级切」要求天然不合；assistant 边界天然消息级（整组 = 回合整体纳入）。
3. 等价性：合法输入下 assistant 边界 ⊆ DSH 平衡边（新 assistant 开始时前回合 tool_calls 必已全部就位）；畸形输入差异由层 2 出口防御兜住。工单授权「等价的配对平衡边回退，Main 锁面定，判据=切点矩阵全绿」。

**实现形（compact.ts 两处切点同形接线，:549 lean + :795-796 rich）**：
- 基线切点照旧 `messages.slice(-keepRecent)`；回退检查 = 若保留段首消息非 assistant 且其所属回合的 assistant 消息在丢弃段，则切点回退扩至该 assistant 消息（含）——该 API 回合整组并入保留段（并行多 tool_call / 多 tool_result 分离消息 / 夹内容消息均随回合整组天然覆盖）。
- **扩大语义**（不收缩）：层 1 只回退扩大保留段，审计 3b 的「保留段合法收缩」面在本实现形下不存在；回退发生时（切点≠原 slice 点）`logForDebugging` 留痕（回退距离 + 保留段尺寸），禁静默。
- 空段回落：仅当消息序列无任何 assistant 边界（全畸形输入）→ 视为不可安全切 → `messagesToKeep=undefined` 全量压缩（工单 §4 既有裁定）。
- keepRecent=0 路径：无切点即无回退面，行为零变更（工单硬约束）。
- 回归点名：wave0186-resume-rebuild（R-085-1 keepRecent 重复边缘语义同域）。
