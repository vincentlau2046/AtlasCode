  2. **顶出**：autocompact 时富 compact 体（`tui/contextBodies/compact.ts:654/977`）调 `reAppendSessionMetadata()` 把 custom-title 钉在**当时** EOF——**但此调用发生在 post-compact 序列写盘之前**；随后 `loop.ts:641-675` `record(messages)` 追加 `buildPostCompactMessages` = `[boundaryMarker, ...summaryMessages, ...messagesToKeep, ...attachments, ...hookResults]` + `recordContentReplacement(replacementRecords)`（content-replacement 记录可达数百 KB）——**全部写在刚钉住的 custom-title 条目之后**。256K 上下文 session 的 post-compact 追加量（摘要 + 保留消息 + 附件 + replacement 记录）轻松 > **64KB（`LITE_READ_BUF_SIZE=65536`，`sessionStoragePortable.ts:17`）** → custom-title 条目被顶出 64KB 尾窗（落在文件中部）。

  4. **恢复缺口**：再钉回仅三时机——① 每 20 条 chain 消息 interval（`METADATA_REWRITE_INTERVAL=20`，`sessionStorage.ts:1090`，至多再写 20 回合内容才重钉）② 干净退出 cleanup（`sessionStorage.ts:454`）③ 下次 compact。**Windows 强杀（关窗/taskkill/crash）→ 退出重钉不跑 → 顶出态持久化到下次启动** = 用户观测面。

- **C-定因④（用户操作面，叠加面）**：compact 后重启进程 = 新 session ID（by design），叠加 C-③ 时旧会话不在当前 case 目录 → 名称全变 + 新 session 复合感知。
