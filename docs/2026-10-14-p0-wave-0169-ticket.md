### D-1 · 每模型 autocompact 窗口（~4–6 文件）

**根因（@0cf6d31 锚定）**：`settings.autoCompactWindow` = **单全局档**（`settings/types.ts:83` schema 单键 + `/autocompact` 命令 `autocompact.tsx:94/104/136/146` 单值写档 + `resolveAutoCompactWindow` `autoCompactWindow.ts:53` 无 model 入参）→ **用户 256K(Qwen38/glm-5.1) + 1M(deepseek-v4-pro) 混配面**：设 256K 档后切 1M 模型仍被 256K 档封顶（auto-compact 提前触发，1M 窗浪费）；反之设 1M 档切 256K 模型 = 触发过晚。

**修复目标（行为面）**：`settings.autoCompactWindow` 扩 **per-model 键控**（`{ [model]: windowPreset }` + `default` 兜底键，向后兼容旧单档 = `default` 键）；`/autocompact` 设档记当前主循环模型；读侧按 `getMainLoopModel()` 取档（无该模型档 → 回落 `default`/缺省）。

**落码面（@0cf6d31 锚定）**：
- ① `settings/types.ts:83` schema 扩 per-model 形（`z.record(model, windowPreset).optional()` 向后兼容：旧单档面 = `default` 键）。
- ② `autoCompactWindow.ts:53 resolveAutoCompactWindow` 加 model 键入参（resolver 按 model 取档，无 → `default` → 缺省）。
- ③ `/autocompact` 命令（`autocompact.tsx`）写档带当前 `getMainLoopModel()`。
- ④ 读侧（`contextHostWiring.ts` autoCompactWindow 档位源接线 + `agentLoopDeps.ts` autoCompact 注入面）按模型取档。
- **Main 定项**：① schema 兼容策略（旧单档 → `default` 键迁移 or 读侧兼容读）② 是否 UI 现形 per-model 档（`/autocompact` 选择器带模型标签）。

**判别单测**：双模型各设不同档（模型 A=128k / 模型 B=1M）→ 切 A 取 128k 档 / 切 B 取 1M 档（修前单全局档红→修后 per-model 绿）+ **旧单档面恒等锚**（未设 per-model 档 = `default` 键，行为 = 修前精确同值）+ 无该模型档回落 default 面。

### D-3 · 摘要 fallback 模型（~1–2 文件）

**根因（@0cf6d31 锚定）**：摘要 LLM 调用（`contextHostWiring.ts:169` port `summarize` = `streamCompactSummary` + `autoCompactRich.ts:92` auto-compact 富路径 `summarize: options.trimmedSummarize`）= **单模型单次调用，被拒/失败无 fallback** → 主模型摘要失败（拒/超时/429）= auto-compact 该轮失败（计熔断计数），小窗模型叠加 F-3a 断路器 = 恢复面失能。

**修复目标（行为面）**：摘要 LLM 调用被拒/失败 → **回落 fallback（small 角色/更轻模型）重试一次**，再失败才计熔断。

**落码面（@0cf6d31 锚定）**：
- `contextHostWiring.ts:169` summarize port 注入处加 fallback 支（经 `CompactPorts` DI 缝，宿主注 fallback summarize = 主摘要调用拒/失败 → 调 small 角色 summarize 重试一次 → 仍失败才抛）。
- 三处统一受益：auto-compact 富路径（autoCompactRich）/ reactive 413 支 / 手动 /compact（均经 port summarize 单口）。
- **Main 定项**：① fallback 模型选择（small 角色 vs 显式轻量模型）② 重试次数（缺省 1 次）③ fallback 触发判定（仅 API 拒/超时/429，非内容错）。

**判别单测**：主摘要拒（mock 主模型 500/429）→ fallback（small）成功（修前无 fallback 红→修后绿）+ **fallback 不触发面恒等锚**（主摘要成功 = 不调 fallback，零额外调用）+ 双失败才计熔断面。

### D-5 · 压缩后 git status 现形（~1 文件，核验缺则补）

**根因（@0cf6d31 锚定）**：post-compact 附件/系统上下文重注 **session 起始快照** 的 git status（`context.ts`/`utils/api.ts` 系统上下文构建面），非 **当前** git status → 压缩后模型看到的 git 状态 = 陈旧（压缩前已改的文件/分支未现形）。

**修复目标（行为面）**：post-compact 重注 **当前** git status（`buildPostCompactAttachments` 宿主实现核验 git status 重注面，缺则补）。

**落码面（@0cf6d31 锚定）**：`buildPostCompactAttachments` 宿主实现（`contextBodies/compact.ts` composePostCompactAttachments 簇）核验 git status 重注面——若现只重注文件态附件（readFileState）不含 git status → 补当前 git status 重注（经 CompactPorts DI 缝，engine React-free 不破）。

**判别单测**：压缩前改文件/切分支 → post-compact 附件含**当前** git status（修前陈旧快照红→修后当前态绿）+ **无 git 变更面恒等锚**（无 git 变更 = git status 重注面 = 修前精确同值）。
