## 0. 波内项一览（2 件，行为面）

| 项 | 上游源（CC 版） | 主诉 | 落码面 |
|---|---|---|---|
| **A · PreModelSwitch/PostModelSwitch 事件** | CC 2.1.251 | 模型切换生命周期钩子（切换前/后各一事件，可配 matcher 按目标模型过滤） | 双 HOOK_EVENTS 事实源（SDK `coreSchemas.ts` + engine `hookEvents.ts`）+ 双 `getMatchingHooks` matchQuery 支 + 双执行器包装（TUI `hooks.ts` / engine `runHooks.ts`）+ TUI 触发点 `model.tsx` 两处切换点 + fire-and-forget 助手 |
| **B · PostToolUse `updatedToolOutput` 全工具化** | CC 2.1.121 | PostToolUse 钩子可改写工具输出（替换 tool_result content），全工具通用（非 MCP 专属） | hooks 域类型面（`types.ts` 3 型）+ `runHooks.ts` interpret/merge + engine `toolHooks.ts` 适配器 + `toolExecution.ts` 消费点（block/toolUseResult 改写）|

### A · ModelSwitch 细目
- **事件面**：`HOOK_EVENTS` 27→29（双事实源同步，AD-45 双解析器映射先例）。
  - SDK 权威源 `src/tui/entrypoints/sdk/coreSchemas.ts`（TUI 经 `coreTypes`/`agentSdkTypes` re-export 消费）。
  - engine 域 `src/hooks/hookEvents.ts`（engine 波/hooks 域单一事实源，engine/config/hooksSchema 经 index 门面消费）。
- **输入 schema**：`coreSchemas.ts` 增 `PreModelSwitchHookInputSchema`/`PostModelSwitchHookInputSchema`（`BaseHookInput & { hook_event_name, old_model, new_model, source }`）；`agentSdkTypes.ts` 增对应 `= any` 类型别名（TUI 松类型先例，与其余 27 事件一致）。
- **matchQuery**：双 `getMatchingHooks` 增 `PreModelSwitch`/`PostModelSwitch` 支，`matchQuery = new_model`（按目标模型过滤，同 PreToolUse→tool_name 语义）。
- **执行器**：TUI `hooks.ts` 增 `executePreModelSwitchHooks`/`executePostModelSwitchHooks`（async generator，无 toolUseContext，`createBaseHookInput(permissionMode, sessionId)` + `getSessionId()` 回退，仿 `executeSessionStartHooks`）；engine `runHooks.ts` 增 `runPreModelSwitchHooks`/`runPostModelSwitchHooks`（仿 5 高频薄包装）。
- **触发点**：`src/tui/commands/model/model.tsx` 两处切换点——`SetModelAndClose.setModel`（/model [name]，source='command'）+ `ModelPickerWrapper.handleSelect`（picker，source='picker'）；切换前 fire Pre、切换后 fire Post；fire-and-forget（`void`，不阻塞 UI，内部超时）；old_model 取组件已知当前模型（picker = `mainLoopModel`；command 支 best-effort）。

### B · updatedToolOutput 细目
- **类型面**（`src/hooks/types.ts`）：`HookJSONOutput` / `HookResult` / `AggregatedHookResult` 各增 `updatedToolOutput?: string`。
- **解析**（`runHooks.ts interpretHookOutput`）：读 `hookSpecificOutput.updatedToolOutput`（CC 嵌套形，主形）+ 顶层 `updatedToolOutput`（双形，顶层 wins，与 updatedInput 读取序一致）→ `result.updatedToolOutput`。
- **聚合**（`runHooks.ts mergeAggregated`）：`if (r.updatedToolOutput) acc.updatedToolOutput = r.updatedToolOutput`（last wins，同 updatedInput）。
- **适配器**（`engine/hooks/toolHooks.ts postToolUse`）：outcome 增 `updatedToolOutput: r.updatedToolOutput`。
- **消费点**（`engine/pipeline/toolExecution.ts`）：`PostToolUseHookOutcome` 增 `updatedToolOutput?: string`；L450 `postOutcome` 消费——`postOutcome?.updatedToolOutput` 在场则改写 `block`（tool_result content 替换）+ `toolUseResult`（原生 Output 同值），再 `return`。

## 1. 零回归约束

- 双 HOOK_EVENTS 事实源 27→29 **同步**（防漂移，AD-45 双解析器映射先例）；事件名集校验测试（`hooks-schema.test.ts` ⑤ 遍历 HOOK_EVENTS）动态适配，无硬编码 27 计数断言 → 不 break。
- 无新命令 / 无新工具 / 无 /help 面增删 → **/help 51 基线恒等 + cmd 29 项零增减**（0.1.42 探针面）。
- `updatedToolOutput` 仅 PostToolUse 消费（PreToolUse/其余事件即便 JSON 带该字段也不改写工具输出）；无钩子配置时 `postOutcome.updatedToolOutput` 恒 undefined → 零行为变更（fail-safe）。
- ModelSwitch 触发 = fire-and-forget（`void`），不阻塞模型切换主路径；无钩子配置时 `getMatchingHooks` 返回空 → 零执行（热路径 `hasHookForEvent` 快跳）。
