### 切片③ 收口记录（Main 2026-10-06）：O-7 PTY 探针定因 + O-2 裁定

- **O-7 = 假象，销项留痕**（判据=真 PTY 字节流终屏态检查同线旧位残留 → 无残留，不立项 footer 行擦修）。
  探针方法：真 PTY（`script -qec 'bun run src/atlascode/launcher.ts'`，40s 捕获，80×24）+ 忠实仿真
  回放（pyte 0.8.2，wcwidth 全角 CJK 模型，与 Ink 侧 EAW stringWidth 计算一致）+ 逐 `?2026l` 渲染
  pass 的 footer 行状态检查：
  - pass 1-3（t≈0-1s）：footer 右栏 = 上下文 tip `◈ xhigh · /effort` → 红字 `Failed to in…`
    （探针环境网关初始化失败，80 列盒截断）→ npm 提示 `AtlasCode is installed via n…`
    （15s 超时；worktree 源码跑未被判 development，正常触发）。
  - pass 4（t=12s tip 轮换）：新 tip `▀ /help 查看全部命令` 写入 = 8 空格 padding + tip 体 + 2 尾
    空格，**完整覆盖旧提示占位 49-77，零同线残留**；pass 5（t=24s `/clear 清屏`）/ 终态
    （t=36s+ `/sessionlist 会话列表`）同净。
  - **假象机制定因**：单个渲染 pass 内 Ink 左→右增量写新 tip（padding 先擦左段 → tip 体依次
    写入），e2e PTY 重建器按行 last-write-wins 捕获了 **pass 内瞬态**（旧 CJK 尾尚未被覆写的
    中间帧）误判为双显。真实字节流擦除语义正确（空格 padding 全覆盖旧内容占位）。
  - **残留面划界**：特定全角字体下的 CJK/歧义宽残留问题（iTerm2/WezTerm/Windows Terminal ×
    Sarasa/Noto，含 O-10 的 ⚡🧠▶⌂ 4 glyph 歧义宽行为）= BR-7 多终端矩阵（0.1.34-1，切片⑤）
