## §2 输出 UX gap 专章（用户核心焦点，方案级）

用户体感「交互信息输出远不及 CC」的**根因收敛为可动手的四件**（按影响排序）：

- **A【P0】渲染增量化（UX-4）**：atlas 全行重绘为主 → 闪烁感/滚动不稳定/终端负载。方案 = tui 渲染层 diff-patch 策略（行级增量更新，CC 形为参照）；验收 = 重绘帧比 ≤ cc 1.5×；**与 0.1.102 撤卸教训正交**（纯渲染策略，不动内容折叠语义）。体量中-大（Ink 渲染层）。
- **B【P0】Edit 权限面修复（#2）**：acceptEdits 下既有文件 Edit 被拒的根因定位（file-not-read 前置门槛与 acceptEdits 覆盖面关系）→ 修形或失败文案明确指引（「先 Read 再 Edit」提示）。小体量高体感收益——agent 绕行脚本 = 回合烧尽 + 输出噪声的直接来源。
- **C【P1】等待态注记（UX-1）**：spinner 加耗时 + token 流量注记（cc 形参照）；前置核 token 计数链 live 状态（0.1.70 断链遗留）。小体量。
- **D【P1】首启可跳过（UX-7）**：主题选择器预置跳过面（settings/env/已选记忆），对齐 cc hasCompletedOnboarding 形。小体量。
